korvarix v2 — Storage Server Setup

Model library host (NFS export + model pulls). Runs on its own box; never talks to the frontend. Order: storage first, then workers.

0 / 0 steps checked
Fill these in first (used to build every command below):

0WireGuard — join this box to the tunnel

On the interface box issue a peer for the storage server, then join here. (Wizard: ./korvarix-cluster.sh → 1) wizard → Interface box → 3) VPN management → issue peer named storage.)

./korvarix-cluster.sh vpn join /path/to/storage-peer.conf   # or the wizard's join step
ip -4 addr show wg0        # note the assigned VPN IP = 10.8.0.20

1Install the Ollama stack (binary only — no daemon needed)

Storage runs no Ollama service. It only hosts the model files, so install the station and use its installer to get the binary + sandbox user + directory layout:

# as root, from the folder with korvarix-cluster.sh
./korvarix-cluster.sh ollama install

This creates korvarix-ollama (unprivileged owner of the models dir), installs the binary under /var/lib/korvarix-cluster/ollama, and does not start any service. Do not run ollama serve here.

2Configure the models dir + allowlist (.env)

cat >> /etc/korvarix-cluster/korvarix.env <<'EOF'

# ---- v2 storage node ----
OLLAMA_BIND=127.0.0.1
OLLAMA_MODELS=/var/lib/korvarix-cluster/ollama/models
# models clients may call (this box PULLS them; workers only mount+serve)
MODELS_ALLOWLIST="oroboros-labs/claude-fable5"
OLLAMA_NUM_PARALLEL=1
OLLAMA_MAX_LOADED=1
EOF

Disk check first: df -h /var/lib/korvarix-cluster — each model needs its blob size on disk (fable5 ≈ 20 GB). Add only what fits.

3Pull the model library (one-time, at wire speed from the CDN)

./korvarix-cluster.sh ollama pull
# verify:
du -sh /var/lib/korvarix-cluster/ollama/models
ls /var/lib/korvarix-cluster/ollama/models/manifests/registry.ollama.ai/oroboros-labs/

Pulls land exactly once here. Every worker mounts this dir read-only — adding a model later = edit allowlist + ollama pull on THIS box, workers see it instantly.

4NFS export (read-only, VPN-only)

apt-get install -y nfs-kernel-server

# exactly ONE export line - read-only, root squashed (workers only read):
sed -i '/ollama\/models/d' /etc/exports
printf '/var/lib/korvarix-cluster/ollama/models 10.8.0.0/24(ro,sync,no_subtree_check,root_squash)\n' >> /etc/exports
exportfs -ra
exportfs -v        # must list exactly ONE entry for the models dir, (ro,...)

systemctl enable --now nfs-server   # (Debian: nfs-kernel-server)
ss -tlnp | grep 2049 || systemctl restart nfs-kernel-server

ro is deliberate: workers only read. Model adds happen on this box via ollama pull, never on workers. If you ever need a worker-side write (pull on a worker), fix the topology instead of making the export rw.

5Firewall — NFS only from the VPN

ufw allow from 10.8.0.0/24 to any port 2049 proto tcp 2>/dev/null \
  || iptables -I INPUT -p tcp -s 10.8.0.0/24 --dport 2049 -j ACCEPT

6Verify from a worker

Run on the worker (after its own setup page):

mount -t nfs 10.8.0.20:/var/lib/korvarix-cluster/ollama/models /mnt/test -o ro
ls /mnt/test/manifests/registry.ollama.ai/oroboros-labs/ && umount /mnt/test && rmdir /mnt/test

7Storage housekeeping (optional but recommended)

# nightly integrity + usage report (edit .env first: set BACKUP_TARGET to a NON-rented box)
./korvarix-cluster.sh backup            # one-off test of the restic backup
./korvarix-cluster.sh health            # wire into cron via menu (cron entry korvarix-health)

The daily ollama daily cron on THIS box re-pulls the allowlist (patch updates land automatically) and prunes non-allowlisted strays — install it via menu 5 → 8. Workers must not run that cron (they hold no writable copy).
